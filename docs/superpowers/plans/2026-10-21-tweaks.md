# Tweaks (Private Injury Log) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a hidden, login-protected Tweaks area to THE BOARD. A long-press on the title opens it. It holds Rob's injury log (injuries, daily check-ins, a pain chart, a new-injury form and an import of his old Google Doc) and the board photo and volume buttons.

**Architecture:**
- **Sign-in:** a second Supabase client (`tweaksSupabase`, with its own storage key) signs Rob in with Supabase Auth. The board's client stays anon.
- **Data:** two new tables with row-level security limited to Rob's user id.
- **Logic:** pure helpers in `src/lib/` (titles, labels, check-in rules, chart geometry) do all the working out.
- **UI:** a `useTweaks` hook holds the session, the data and the actions. Presentational screens in `src/tweaks/` get their data as props, and `App.jsx` owns `view` and navigation, as it does for every other screen.

**Tech Stack:** React 19, Vite 8, Vitest 4 + Testing Library (jsdom), lucide-react, Supabase JS v2. No new dependencies in `board-app`.

**Spec:** `docs/superpowers/specs/2026-10-21-tweaks-design.md`

## Review Focus

1. **Notes with blank lines between paragraphs.** Imported notes have them. They should show as written, not run together. Tested in Task 15.
2. **Two check-ins on the same date.** One day in the import has two. The chart should draw one point for that day, the list should show both, and the sheet should open the one created last. Tested in Tasks 9 and 14.
3. **A session that expires while Rob is in Tweaks.** A read gets 42501 or 401. The password sheet should come back rather than a blank screen, and anything typed should survive as a draft. Tested in Tasks 11 and 17.
4. **Saving with no signal at the wall.** The sheet should stay open, keep the notes and leave the draft in place. Tested in Task 13.
5. **An injury with zero or one check-ins.** There should be no chart (no NaN geometry), and the hub should say "No check-ins yet". A check-in dated in the future should read "Checked in today", not "-2 days ago". Tested in Tasks 8 and 14.

- [ ] **Step 2: Write `schema.sql`**

Use the two `create table` statements and the index from the spec, as they are. Then add this, which replaces the spec's `<ROB_USER_ID>` placeholders: it looks the id up, so Rob never has to paste it.

```sql
alter table injuries enable row level security;
alter table injury_checkins enable row level security;
revoke all on injuries, injury_checkins from anon;
grant select, insert, update, delete on injuries, injury_checkins to authenticated;

do $$
declare rob uuid := (select id from auth.users where email = 'tweaks@example.com');
begin
  if rob is null then
    raise exception 'Create the tweaks@example.com user in Authentication first';
  end if;
  execute format('create policy "Rob only" on injuries for all to authenticated using (auth.uid() = %L) with check (auth.uid() = %L)', rob, rob);
  execute format('create policy "Rob only" on injury_checkins for all to authenticated using (auth.uid() = %L) with check (auth.uid() = %L)', rob, rob);
end $$;
```

- [ ] **Step 3: Write `check-sql.mjs`, and watch it pass**

Install PGlite outside the app:

The script works against an in-memory PGlite:
1. Create stand-ins for what Supabase provides:
   - `create schema auth; create table auth.users (id uuid primary key, email text)`;
   - `auth.uid()`, returning `nullif(current_setting('request.jwt.claim.sub', true), '')::uuid`;
   - roles `anon` and `authenticated`, with `grant usage on schema public, auth to anon, authenticated` and `grant execute on function auth.uid() to anon, authenticated`.
2. Check that running `schema.sql` **before** the user exists raises "Create the tweaks@example.com user".
3. Insert user `00000000-0000-0000-0000-000000000001` / `tweaks@example.com`, then run `schema.sql`.
4. As `authenticated` with that `sub`: inserting an injury and a check-in works and reading them back returns 1 row each. A check-in with `pain_low = 1.25` or `pain_high < pain_low` fails with a check violation.
5. As `authenticated` with another `sub`: the select returns 0 rows, and an insert fails (42501).
6. As `anon`: the select fails with "permission denied".

### Task 14: Pain chart

**Files:**
- Create: `board-app/src/lib/painChart.js`, `board-app/src/lib/painChart.test.js`, `board-app/src/tweaks/PainChart.jsx`

**Interfaces:**
- Consumes: `daysBetween` from `dates.js`.
- Produces:
  - `CHART = { W: 300, H: 100, LEFT: 22, RIGHT: 6, TOP: 6, BASE: 82, DOTS: 94 }`
  - `painChartGeometry(checkins, { endDate, boardDays }): null | { yMax, points: [{ date, x, yLow, yHigh, yMid, yPeak }], dots: [{ date, x }] }`
    - It returns `null` when there are fewer than 2 distinct dates.
    - Check-ins on the same date combine into one point: the lowest low, the highest high and the highest peak.
    - `span = daysBetween(firstDate, endDate)`
    - `x(d) = LEFT + daysBetween(firstDate, d) / span * (W - LEFT - RIGHT)`
    - `yMax = max(5, ceil(max of every high and peak))`
    - `y(v) = BASE - v / yMax * (BASE - TOP)`
    - `yPeak` is null when there's no peak.
    - `dots` are only the board days from `firstDate` to `endDate`.
  - `PainChart({ checkins, endDate, boardDays })`. It renders nothing when the geometry is null. Otherwise it draws `<svg data-chart="pain" viewBox="0 0 300 100">` with:
    - a gridline at `yMax` and one at half of it, with mono labels;
    - the low–high band as a `#D9552B33` polygon;
    - the midline as a 2px `#D9552B` polyline;
    - peaks as 3px `#D9552B` dots;
    - board days as 3px `#C08552` dots at `DOTS`;
    - the caption "● days on the board" when there are any dots.
