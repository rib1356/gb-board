# Hold Heatmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Heatmap section to the trophy screen. It shows the board photo with a glow over every hold that problems use for hands, so the crew can spot bare holds that are free to set on.

**Architecture:**
- A pure module, `src/lib/heatmap.js`, groups the hold marks saved on live problems into spots and counts the problems on each.
- `src/stats/Heatmap.jsx` draws the photo, an SVG layer of glows and a legend.
- `BoardStatsScreen` shows it as its last section, and `App` passes the board photo URL.

No new data and no SQL.

**Tech Stack:** React 19, Vite 8, Vitest 4 + Testing Library (jsdom). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-votes-and-heatmap-design.md` (Part 2). Read it alongside this plan.

## Global Constraints

- **Branch `feat/heatmap` from `main`.** Never commit to `main`. Push every commit straight away.
- **Commit messages** are conventional (`feat:`, `fix:`, `test:`). Each ends with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Commands run in** `/Users/roblatticetraining/projects/boardClimbing/board-app`. One file: `npx vitest run <path>`. Everything: `npm run lint && npm test && npm run build`.
- **No schema change, no SQL, no writes to the live database.**
- **Which problems count:** live problems (as `listProblems` returns them) whose `photo_url` equals the board's current `photo_url`.
- **Which marks count:** holds of type `start`, `hold` and `finish`. **`foot` is ignored**, including volume sides marked as feet.
- **Heat** is the number of different problems using a spot. A problem marking two points in one spot counts once.
- **Grouping:**
  - Holds without `face` join the nearest existing **hold** spot (never a volume side's spot) within `MERGE_RADIUS = 0.02` (fractions of the photo's width).
  - Distance is `Math.hypot(dx, dy * aspect)`, where `aspect = naturalHeight / naturalWidth`.
  - A spot's position is the mean of its marks.
  - Volume sides (holds with `face`) group by `` `${face.volumeId}|${face.faceId}` ``, never by distance, and are drawn at the mean of their marks.
  - Problems are processed oldest first (`created_at`, then `id`), each problem's holds in order.
- **Copy, exactly:**
  - Section title: "Heatmap"
  - Section note: "no glow = free to set on"
  - Legend: "1 problem" → "{max} problems", and "No glow: never used as a handhold"
  - Image alt: "Board heatmap"
- **Placement:** the last section on the trophy screen. It's hidden when the board has no photo, or no live problem is on the current photo.
- **No interaction** on the heatmap: no taps and no separate full-size view.
- **Glows must not hide bare holds.** Each glow is about one hold in size, and the photo isn't darkened enough to hide holds.

## Review Focus

1. **Problems on the photo whose holds are all feet:** the section shows the bare photo, and the legend shows only the "No glow" line, with no "0 problems" and no NaN. Tested in Task 2.
2. **The photo hasn't loaded yet** (so `aspect` is unknown): the photo shows with no glows and nothing crashes. Glows appear once it loads. Tested in Task 2.
3. **The busiest spot is used by one problem:** the legend reads "1 problem" only, never "1 problem → 1 problems". Tested in Task 2.
4. **Input order:** `listProblems` returns newest first, and edits reorder it. The spots must come out the same whatever order the problems arrive in. Tested in Task 1.
5. **A re-shot board photo:** every problem is now on an older photo, so the section disappears instead of showing glows in the wrong places. Tested in Task 2.

### Task 1: Branch and the heatmap module

**Interfaces:**

- [ ] **Step 2: Write the failing tests** in `board-app/src/lib/heatmap.test.js`. Use these helpers:
  - `P(id, created_at, holds, photo_url = 'photo-1')`
  - `H(x, y, type = 'hold')`
  - `F(volumeId, faceId, x, y, type = 'hold')`, a hold with `face: { volumeId, faceId, label: 'Vol Top', points: [] }`

```js
describe('heatSpots', () => {
  it('merges marks of the same hold from different problems, and counts each problem once', () => {
    const problems = [
      P('a', '2026-10-01T00:00:00Z', [H(0.5, 0.5, 'start'), H(0.505, 0.5)]),
      P('b', '2026-10-02T00:00:00Z', [H(0.51, 0.505, 'finish')]),
    ];
    const spots = heatSpots(problems, 'photo-1', 1);
    expect(spots).toHaveLength(1);
    expect(spots[0].heat).toBe(2);
    expect(spots[0].x).toBeCloseTo((0.5 + 0.505 + 0.51) / 3);
    expect(spots[0].face).toBe(false);
  });

  it('keeps holds further apart than the radius as separate spots', () => {
    const spots = heatSpots([P('a', '2026-10-01T00:00:00Z', [H(0.5, 0.5), H(0.53, 0.5)])], 'photo-1', 1);
    expect(spots.map((s) => s.heat)).toEqual([1, 1]);
  });

  it('measures vertical gaps in real proportions using the aspect ratio', () => {
    const problems = [P('a', '2026-10-01T00:00:00Z', [H(0.5, 0.5), H(0.5, 0.515)])];
    expect(heatSpots(problems, 'photo-1', 1)).toHaveLength(1);    // 0.015 apart
    expect(heatSpots(problems, 'photo-1', 1.5)).toHaveLength(2);  // 0.0225 apart
  });

  it('ignores foot holds, including a volume side used as a foot', () => {
    const problems = [P('a', '2026-10-01T00:00:00Z', [H(0.2, 0.2, 'foot'), F('v1', 'top', 0.4, 0.4, 'foot'), H(0.6, 0.6)])];
    expect(heatSpots(problems, 'photo-1', 1)).toEqual([{ x: 0.6, y: 0.6, heat: 1, face: false }]);
  });

  it('groups volume sides by which side they are, not by distance', () => {
    const problems = [
      P('a', '2026-10-01T00:00:00Z', [F('v1', 'top', 0.4, 0.4), H(0.401, 0.401)]),
      P('b', '2026-10-02T00:00:00Z', [F('v1', 'top', 0.42, 0.4)]),
    ];
    const spots = heatSpots(problems, 'photo-1', 1);
    expect(spots).toHaveLength(2);
    expect(spots.find((s) => s.face)).toMatchObject({ heat: 2, y: 0.4 });
    expect(spots.find((s) => s.face).x).toBeCloseTo(0.41);
    expect(spots.find((s) => !s.face).heat).toBe(1);
  });

  it('leaves out problems marked on another photo', () => {
    const problems = [P('a', '2026-10-01T00:00:00Z', [H(0.5, 0.5)], 'photo-0'), P('b', '2026-10-02T00:00:00Z', [H(0.7, 0.7)])];
    expect(heatSpots(problems, 'photo-1', 1)).toEqual([{ x: 0.7, y: 0.7, heat: 1, face: false }]);
  });

  it('gives the same spots whatever order the problems arrive in', () => {
    const problems = [
      P('a', '2026-10-01T00:00:00Z', [H(0.5, 0.5)]),
      P('b', '2026-10-02T00:00:00Z', [H(0.515, 0.5)]),
      P('c', '2026-10-03T00:00:00Z', [H(0.53, 0.5)]),
    ];
    expect(heatSpots([...problems].reverse(), 'photo-1', 1)).toEqual(heatSpots(problems, 'photo-1', 1));
  });
});

describe('problemsOnPhoto', () => {
  it('keeps only problems set on the given photo, and none without one', () => {
    const a = P('a', '2026-10-01T00:00:00Z', [], 'photo-1');
    const b = P('b', '2026-10-01T00:00:00Z', [], 'photo-0');
    expect(problemsOnPhoto([a, b], 'photo-1')).toEqual([a]);
    expect(problemsOnPhoto([a, b], null)).toEqual([]);
  });
});
```
