# Grade & Star Votes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let everyone who has sent a problem vote on its grade and stars. They're asked on their first send, and can vote or change their vote from the problem page at any time. A problem's stars become the average of the votes. Grade votes are shown beside the hand-set grade and never replace it.

**Architecture:**
- Votes live in the new `votes` table (one row per climber per problem). It is loaded once with the board, like the board's sends.
- Which votes count, averages, grade tallies and chip choices all come from a pure module, `src/lib/votes.js`.
- `App.jsx` holds `boardVotes` next to `boardTicks`. A small `VotePicker` component draws the grade chips and stars for both the send form and the problem page.
- Classics on the trophy screen ranks by the vote average.

**Tech Stack:** React 19, Vite 8, Vitest 4 + Testing Library (jsdom), lucide-react, Supabase JS v2. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-votes-and-heatmap-design.md` (Part 1). Read it alongside this plan.

## Global Constraints

- **Branch `feat/votes` from `main`.** Never commit to `main`. Push every commit straight away.

- **Vote shape:** `{ id, problem_id, climber, grade: string | null, stars: 1–5 | null, created_at }`. A saved row always has at least one of `grade` / `stars`.
- **A vote counts** only while its `climber` has a named send (`sent_by === climber`) of that problem in the board's sends. This is worked out each time, never stored.

  - Problem-page failure: "Could not save your vote — check your connection and try again."

### Task 1: Branch and the votes module

**Files:**
- Create: `board-app/src/lib/votes.js`
- Test: `board-app/src/lib/votes.test.js`

**Interfaces:**
- Consumes: `GRADES` (`./grades`), `gradeNumber` (`./problemList`).
- Produces:
  - `countedVotes(votes: Vote[], ticks: Tick[]): Vote[]`: the votes whose climber has a named send of that problem.
  - `starSummary(problem, counted: Vote[]): { average: number, count: number, stars: number, legacy: boolean } | null`.
    - It filters `counted` by `problem.id`. Votes without stars don't count towards it.
    - With star votes: `stars = Math.round(average * 2) / 2` and `legacy: false`.
    - With no star votes but a `problem.rating`: `{ average: rating, count: 0, stars: rating, legacy: true }`.
    - Otherwise `null`.
  - `gradeVoteCounts(problemId: string, counted: Vote[]): { grade: string, count: number }[]`: easiest first. Null and unparseable grades are dropped.
  - `gradeChoices(currentGrade: string | null, myGrade: string | null): string[]`: the grade below, the current grade and the grade above, clamped to V0–V18, plus `myGrade` if it isn't one of them, in grade order. An ungraded or unparseable `currentGrade` gives `[]`.
  - `voteFor(votes: Vote[], problemId: string, climber: string | null | undefined): Vote | null`
  - `replaceVote(votes: Vote[], problemId: string, climber: string, row: Vote | null): Vote[]`: drops that climber's row for the problem, then appends `row` if it isn't null.

### Task 2: Load and save votes

**Files:**
- Modify: `board-app/src/lib/board.js` (add after `listBoardTicks`)
- Test: `board-app/src/lib/board.test.js`

**Interfaces:**
- Consumes: the `supabase` client.
- Produces:
  - `listBoardVotes(boardId: string): Promise<Vote[]>`
    - `from('votes')`, `select('id, problem_id, climber, grade, stars, created_at, problems!inner(board_id)')`, `eq('problems.board_id', boardId)`.
    - Ordered by `created_at` then `id`, ascending, and read in pages of `TICK_PAGE` until a page comes back **empty**. This is the same loop as `listBoardTicks`.
  - `saveVote(problemId: string, climber: string, { grade, stars }): Promise<Vote | null>`
    - If either value is set, it calls `from('votes').upsert({ problem_id, climber, grade, stars }, { onConflict: 'problem_id,climber' }).select().single()` and returns the row.
    - If both are `null`, it calls `from('votes').delete().eq('problem_id', problemId).eq('climber', climber)` and returns `null`.
    - It throws on any error.
