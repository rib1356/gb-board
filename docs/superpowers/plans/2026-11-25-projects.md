# Your Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One tap on a problem logs today as a project session for the picked climber; their projects show at the top of the list, go cold after 28 days, and a send shows how many sessions it took.

**Architecture:** A new `project_sessions` table (already created) holds one row per climber, problem and day. `App` loads the board's rows once, beside `boardTicks`, and every view filters to the picked climber. All project facts (active, cold, sessions to send) are derived in a pure `lib/projects.js`. Tweaks' `boardDays` also takes Rob's session days.

**Tech Stack:** React + Vite, Vitest + Testing Library, oxlint, Supabase JS.

**Spec:** `docs/superpowers/specs/2026-11-25-projects-design.md`

## Global Constraints

- The table exists already (created and probed with the anon key on 2026-11-25): RLS off, CRUD granted to anon. No more SQL.
- Session date: `todayISO()` from `src/lib/warmup.js`, the same clock as the send form. Not `localDate()`.
- Cold: last worked `>= 28` days before today (`COLD_AFTER_DAYS = 28`, via `daysBetween` in `src/lib/dates.js`).
- Copy, verbatim: button "Worked it today" / "Worked today" with a ✓ (`Check` icon, `aria-pressed="true"`); heading "Your projects"; toggle "Gone cold (N)"; list row "N sessions · last <dayLabel>"; problem page "N sessions · since <shortDate>"; send tag "N sessions" or "First session"; "1 session" in the singular. Error: "Could not save that — check your connection and try again."
- Date labels: `dayLabel(date, today)` and `shortDate(date, today)` from `src/lib/injuries.js`.
- Per climber, always: nothing project-related renders with nobody picked, and another climber's rows never show.
- Project sessions never feed send counts (logbook sessions, progress, crew board, FAs, flashes, heatmap, warm-ups). Tweaks board days are the one exception.
- Branch `feat/projects`, stacked on `feat/warmup-notes` so one local run tests both. Run commands from `board-app/`.

## Review Focus

1. Two quick taps on Worked it today while the first save is in flight: one `addProjectSession` call, and the button ends up "Worked today".
2. A failed save or undo: the button flips back and the error shows; Your projects matches what's saved.
3. Sending on the same day as a tap: the project leaves Your projects and the send shows "First session".
4. A send backdated before later session rows: those rows don't count towards sessions to send, and the problem is not a project.
5. Another climber's sessions on the same problem: invisible to you, and they don't change your counts.

### Task 4: Worked it today on the problem page

**Files:**
- Modify: `src/App.jsx` (problem page action row ~line 1265; sends list ~line 1316)
- Test: `src/App.test.jsx` (new `describe('App (projects)')`)

**Interfaces:**

Behaviour, from the spec's Problem page section:
- With a climber picked, the form closed, and no send by them (`sentProblemIds(boardTicks, name)`), the row is `[Worked it today] [+ Log a send]`. With a send by them, only Log a send, as now. With nobody picked, the existing prompt. While the send form is open, neither (as now).
- Tap when not worked today: add an optimistic row `{ problem_id, climber, worked_on: todayISO() }` to `projectSessions`, then `addProjectSession`. Tap when worked today: remove today's row, then `removeProjectSession`. On failure, put the state back and `setError('Could not save that — check your connection and try again.')`. While a save is in flight (a ref, so a fast double tap can't slip through), taps do nothing.
- Under the row, while the problem is one of your projects (active or cold): "N sessions · since <shortDate(firstWorked, today)>".
- In the sends list, on the climber's own first send of this problem (in `firstSendIds(ticks)` and `t.sent_by === name`), when `sessionsToSend` has the problem: a tag "N sessions" or "First session", styled like the Repeat label but `#C08552`.
